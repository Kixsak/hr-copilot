# HR Copilot — Independent Portfolio Demonstration

A **local proof-of-concept** for role-aware natural-language analytics. Built with Python, Streamlit, pandas, Claude via the Anthropic API, and a server-side query/permission layer. This is **not** a production deployment or an independently certified security product.

## What it demonstrates

- Business question → LLM tool call (`hr_query`) → validated Python query → role-scoped result.
- Role-based access checks enforced by application code, rather than only by the model prompt.
- Data cleaning, small-cell suppression, audit records, and automated tests.
- Reproducible local Docker Compose setup.

## Demo

A 3-minute walkthrough (role-scoped answers, backend refusals, HRBP review queue, audit log) is in [`demo/hr_copilot_demo.webm`](demo/hr_copilot_demo.webm). It was recorded against the bundled synthetic data with `claude-haiku-5-5`.

## Data provenance and limitations

`data/` contains **fully fictional demonstration records** (1,853 active rows, 60 February 2026 leavers), unrelated to any real employees and generated by `generate_demo_data.py` with a fixed seed (`python generate_demo_data.py` reproduces it). A handful of deliberately dirty rows exercise the cleaning pipeline and the HRBP review queue. Figures produced from these data are for demonstration only. No evaluation sets, model outputs, audit logs, accounts, or credentials are included.

## Quick start (Docker Compose)

1. Install Docker Desktop / Docker Engine with Compose.
2. Copy `.env.example` to `.env`. Set `HRC_BOOTSTRAP_PASSWORD` to a strong local demo password (minimum 8 characters).
3. Set `ANTHROPIC_API_KEY` to your own [Anthropic API key](https://console.anthropic.com/). Optionally set `CLAUDE_MODEL` (`claude-haiku-5-5` by default; `claude-sonnet-5-5` and `claude-opus-5-5` also work). Each question makes one or more paid API calls; the per-answer token usage and estimated cost are shown under every reply.
4. Run `docker compose up --build`.
5. Open `http://localhost:8501` (or your configured `HRC_PORT`).
6. Demo users created at initialisation: `group_head` (R1), `bg1_head` (R2), `bu01_head` (R3), `hrbp_bu07` (R4), and `admin` (R5). Initial passwords match `HRC_BOOTSTRAP_PASSWORD`. Use **local demo only**.
7. Stop with `docker compose down`. To reset the local demo state, run `docker compose down -v` (deletes the local volume).

The web application requires valid model credentials for LLM-powered responses. **The automated tests do not require an API key**. Do not publish demo passwords or expose this Compose configuration on a public network.

## Tests

```bash
python -m pip install -r requirements.txt
python -m pytest -q
```

The included `run_eval.py` is a framework for authoring your own evaluation set (see `eval/README.md`). No model-evaluation score is claimed for the demo dataset.

## Architecture

```text
Streamlit UI (app.py)
  → authentication (auth.py)
  → Claude tool loop (agent.py)
  → validated role-scoped query (query.py)
  → cleaned synthetic CSV data (clean.py, data/)
  → audit events and aggregated response
```

## Example demo walkthrough

1. Log in as `bg1_head`; ask for a headcount by BU within your permitted BG.
2. Ask for a different BG's personnel statistics; observe the backend refusal.
3. Ask for an employee list as an executive user; observe the detail-access restriction.
4. Log in as `hrbp_bu07`; demonstrate the assigned BU scope and allowed detail access.
5. Show `tests/` and explain how role restrictions and error cases are checked without relying on the LLM to enforce them.

## Key engineering decisions

- The model interprets requests and formats responses; pandas executes deterministic calculations.
- `query.py` checks role and organisational scope before releasing query results.
- The model name and API key are configured via environment variables (`CLAUDE_MODEL`, `ANTHROPIC_API_KEY`), not embedded in `agent.py`.
- Runtime state is excluded from Git and Docker image build context.

## Security and scope

This demonstration has not undergone an external penetration test, full threat modelling, or production hardening. It should be used on localhost only. Check repository history for secrets before publishing.
